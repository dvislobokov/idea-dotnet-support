io.github.dotnetsupport · v0.1.0 · платформа IntelliJ 2026.1+ · IDEA (в т.ч. Community), GoLand, PyCharm, WebStorm

Rider-подобная работа с .NET в вашей IDE на платформе IntelliJ — без ReSharper

Панель Solution, сборка, запуск и отладка, тесты и покрытие, NuGet, EF Core, мониторинг процесса. Семантику C# даёт roslyn-language-server, отладку — свой DAP-клиент к dotnet-debugger-dap, всё остальное — dotnet CLI. Никакого собственного парсера и никакого закрытого бэкенда.

Что внутри

Основной сценарий .NET-разработчика — целиком

Открыть solution → писать код → собрать → запустить → отладить → прогнать тесты → поставить пакет. Всё, что ниже, сверено с кодом плагина (COMPARE.md). Метка тесты — покрыто unit-тестами, но в живой IDE ещё не проверялось; частично — есть оговорка.

Solution view

  • .sln, .slnx и фильтры .slnf; несколько solution в папке — все находятся
  • Узел Dependencies по каждому TFM: Imports, Packages (с транзитивными), Projects (транзитивно), Assemblies, Analyzers, Frameworks
  • File nesting как в Rider, Show All Files («глаз»), Compile Remove, DependentUpon, linked-файлы с бейджем
  • Add ▸ New / Existing Project, Solution Folder, Project Reference, Assembly Reference; Remove from Solution; Convert to .slnx
Свойства проекта читаются из XML без вычисления Condition / $(…).

Редактор C# через Roslyn

  • Ошибки компилятора и анализаторов в редакторе, серые неиспользуемые using
  • Completion с авто-using, Ctrl+P со всеми перегрузками, Ctrl+Q, inlay hints, semantic highlighting (кэш — раскраска до загрузки solution)
  • Alt+Enter: quick fixes, рефакторинги Roslyn, вложенные варианты и Fix All в Document / Project / Solution
  • Shift+F6 rename с переименованием файла; Go to Declaration / Implementation; декомпилят фреймворка read-only
  • Type Hierarchy Ctrl+H, Call Hierarchy Ctrl+Alt+H, Problems → Project Errors по всему solution тесты
Без сервера работают эвристики: подсветка, Structure view, folding, отступы, Go to Class, live/postfix templates, Surround With.

Отладчик

  • Свой DAP-клиент на XDebugger API → работает и в IDEA Community
  • Точки останова: строчные (только на строках с кодом), Condition, Hit count, Log message; Exception breakpoints с типами (System.IO.*, !…)
  • Step Over / Into / Out, Run to Cursor, Set Next Statement, async call stack, кадры фреймворка серым
  • Variables постранично, Set Value, Evaluate / Watches / hover, completion в выражениях, inline values
  • Attach to Process (группа «.NET»), отладка тестов, ввод в Debug Console, Rerun с пересборкой
Адаптер dotnet-debugger-dap (MIT, ICorDebug): только .NET Core / 5+. Проверено вживую и UI-роботом.

Тесты и покрытие

  • xUnit / NUnit / MSTest по атрибутам; окно Unit Tests: Explorer (Project → Class → Method) и сессии результатов
  • ▶ у метода и класса, --filter, Rerun Failed, Debug Selected Tests
  • Run with Coverage: coverlet → полосы в gutter, окно .NET Coverage, проценты в дереве проекта
  • Microsoft.Testing.Platform (MSTest runner, xunit.v3, TUnit) — запуск, TRX, фильтры, покрытие тесты
Дерево результатов строится по TRX после завершения dotnet test; консоль идёт live. Отладка MTP-тестов — нет.

NuGet

  • Окно NuGet: Packages / Sources / Folders / Log; область Solution или проект, Prerelease, «→ latest», multiple
  • Карточка пакета: версии, описание, лицензия, зависимости по TFM, Install / Update / Downgrade / Remove по проектам
  • Upgrade Packages in Solution, Quick List Alt+Shift+N, auto-restore при правке .csproj / nuget.config
  • Приватные фиды с учётными данными (PasswordSafe + nuget.config), completion id и версий в PackageReference
Только V3-фиды; Central Package Management читается, но правки из окна CPM не учитывают.

EF Core

  • Add / Remove Migration, Update Database (и откат), Generate SQL Script, Drop Database, Create Migration Bundle, Scaffold DbContext
  • Один диалог: startup project и DbContext подбираются сами, окружение, конфигурация / TFM, предпросмотр команды
  • Окно EF Core: миграции со статусом applied / pending, «model has changes not in a migration», Update to Here, Script from / to Here
  • Gutter у DbContext и миграций; генератор Design-Time Factory; разбор ошибок dotnet-ef с кнопками-исправлениями
Design-пакет добавляется автоматически; Drop только после ввода имени базы.

.NET Monitor

  • Графики по процессу: CPU, память (working set + GC heap), allocation rate, time in GC, requests p95, exceptions, thread pool queue
  • Thread Dump (dotnet-stack): одинаковые стеки свёрнуты, кадры приложения кликабельны
  • Heap Snapshot (dotnet-gcdump) с Δ к любому из 8 прошлых снимков
  • Memory Dump (dotnet-dump + SOS): типы → объекты → Who Holds It (gcroot), Fields, SOS Console, Save Dump As…
Внешние dotnet-* tools, ставятся из настроек. CPU-профилирования (dotnet-trace) пока нет.

ASP.NET Endpoints + Services

  • Окно Endpoints: minimal API (MapGet… с MapGroup) и контроллеры ([Route], [HttpX]), параметры маршрута, base URL из launchSettings
  • Generate HTTP Request в <Project>.http, Open in Browser, Copy URL, globe в gutter, автопересканирование
  • Конфигурации «.NET Project» в окне Services: статус, консоли, перезапуск списком, ссылка на адрес из «Now listening on» тесты
Маршруты — по литералам; из констант / nameof / Razor Pages не собираются.

Сборка и запуск

  • Build / Rebuild / Clean / Restore → окно Build с деревом ошибок; ошибки последней сборки в редакторе, пока сервер не готов
  • Переключатель Debug / Release + TFM в тулбаре; Smart Restore; Measure Build Performance; Run MSBuild Target…
  • Run configuration «.NET Project»: run / watch / test, launch profile, окружение через dotnet run -e, авто-открытие браузера
  • Конфигурации сами по launchSettings.json; кликабельные стектрейсы, раскраска уровней логов, сворачивание кадров фреймворка
Один тип конфигурации; Compound и .NET Executable — нет.
Работа с проектом

То, за чем в Rider ходят в диалоги, — здесь тоже диалоги

Всё пишется в файлы проекта точечными правками: отступы и остальной текст .csproj / .sln не трогаются.

01

New .NET Project с опциями шаблона

Шаблоны из dotnet new list, «More templates…» с nuget.org, Language, Framework из установленных SDK и параметры выбранного шаблона (--use-program-main, --auth, Test runner = Microsoft.Testing.Platform…). В IDEA — мастер New Project → «.NET», в GoLand / PyCharm / WebStorm — генератор. тесты

02

Properties…

Вкладки Application (TFM, AssemblyName, RootNamespace, OutputType, LangVersion, Nullable, ImplicitUsings), Build (TreatWarningsAsErrors, NoWarn, AnalysisLevel…), Package (PackageId, Version, License, README…). Пустое значение возвращает умолчание SDK. тесты

03

Rename Project

ПКМ → Rename Project… или F2 / Shift+F6 на узле: файл проекта, папка по галочке, .sln / .slnx, ProjectReference других проектов, run configurations — одной отменяемой командой. тесты

04

Solution filters и честное содержимое

.slnf — узел «AppOnly (1 of 4 projects)», пустые solution folders обрезаются. Файлы, вынутые из глобов (Compile Remove, DefaultItemExcludes), скрыты; linked-файлы из-за пределов проекта показаны по пути Link с бейджем.

05

Completion по схеме MSBuild

Своя составная схема из 12 фрагментов (~283 свойства, ~44 item-а): теги по месту, атрибуты, значения, Quick Doc со ссылкой на документацию, предупреждение о значении вне перечисления, подсветка $() / @() / %(). Плюс completion id и версии пакетов.

06

New → .NET и New → C# Class

30 генераторов по категориям: C#, ASP.NET (Controller, Minimal API, Middleware, Background Service…), Tests (класс, Fixture, Test for Selected Class), EF Core, Configuration (Directory.Build.props, Dockerfile, GitHub Actions…), «From SDK Template…». Namespace — по RootNamespace и папке, file-scoped по .editorconfig или TFM.

07

SDK и инструменты

Проверка dotnet и global.json (rollForward) при открытии с нотификациями Download SDK; «.NET on This Machine» с таблицами SDK / runtime; страница .NET Tools ставит и обновляет все 9 внешних инструментов плагина.

08

Форматирование

Ctrl+Alt+L → CSharpier (0.x и 1.x, HTTP-сервер на проект) или dotnet format (сервером, когда загружен); Auto выбирает CSharpier, если репозиторий им пользуется. Меню .NET → Format / Verify Formatting для проекта целиком, как в CI.

Как устроено

Никакой собственной семантики C# внутри IDE

Всё, что в Rider «мгновенно и в процессе», здесь — через процесс. Зато любой компонент можно заменить, обновить и посмотреть его лог в ~/idea-dotnet-logs.

IDE на платформе IntelliJ 2026.1+Solution view · Build · Run · XDebugger · Services · Problems · Hierarchy · платформенный LSP-клиент
dotnet CLI

build, run, test, sln, add package, msbuild -getProperty, new, format, ef. Каждая команда — в лог commands/.

→
roslyn-language-server

Внешний dotnet tool (.NET 10). Ошибки, completion, навигация, rename, code actions, semantic tokens, иерархии — через intellij.platform.lsp, с memo-кэшем ответов и прогревом.

→
dotnet-debugger-dap

Свой DAP-клиент DapConnection поверх XDebugger API. Не зависит от платформенного DAP-модуля, поэтому работает в IDEA Community.

→
dotnet-* tools

dotnet-counters, dotnet-stack, dotnet-gcdump, dotnet-dump, dotnet-ef, csharpier, upgrade-assistant. Установка из Settings → .NET.

Сервер главныйПока roslyn-language-server готов, эвристики уступают: раскраска, folding, Structure, ошибки последней сборки, отступы — от сервера.
Эвристики — пока сервера нетЛексер и сканер объявлений по токенам работают всегда: в файлах вне solution, во время загрузки, в IDE без LSP-модуля. Эвристика только предлагает и никогда не источник ошибок.
Правда о проекте — из файловXML .csproj и obj/project.assets.json после restore; точные значения (TargetPath, targets) — через dotnet msbuild.

Не входит

Чего на демо не будет

Это следствие подхода, а не недоделки: всё, чему нужна семантика языка внутри IDE, живёт во внешнем сервере, а его нет для Razor и XAML.

Razor / Blazor / .cshtmlЯзыка нет вообще: редактор — plain text / HTML платформы. Для Blazor и MVC это блокер.
XAML, F#, VB.NETXAML — как XML (nesting и шаблоны WPF есть); F# и VB — только иконки и типы проектов в дереве.
Publish и контейнерыНет Publish в папку / IIS / Azure / Docker, нет Aspire; Docker-плагин платформы работает сам по себе.
Hot Reload и Edit & Continuedotnet watch есть как команда конфигурации, но без индикации; при отладке — нет.
Инспекции и Code Cleanup ReSharperТолько анализаторы Roslyn и severity из .editorconfig; профилей Cleanup нет, есть Fix All и dotnet format.
Отладка .NET Framework, Mono, remoteАдаптер — только CoreCLR; attach по SSH / Docker / WSL нет; stepIn в async-метод не работает (Run to Cursor как обход).
Демо-сценарий

10 минут — от открытия папки до memory dump

По шпаргалке из раздела 7 COMPARE.md. Рядом с каждым шагом — где это лежит в IDE.

Открыть папку с solution

Открыть папку (не файл). Панель Project переключится на Solution; при нескольких solution сервер спросит «Select Solution for Language Server». Показать Dependencies по TFM и «глаз» Show All Files.

0:00

Services: запустить веб-проект

Run configurations уже созданы по launchSettings.json. Окно Services → Run: статус, консоль с раскраской логов, ссылка на адрес из «Now listening on». Открыть окно Endpoints, кликнуть globe в gutter → .http.

1:00

Редактор: completion и postfix

Открыть .cs — виджет «Roslyn: X.sln». Набрать тип из неимпортированного namespace (авто-using), Ctrl+P на перегрузках, expr.notnull + Tab, ctor / prop live templates, Ctrl+Alt+T Surround With.

2:30

Alt+Enter и Fix All

Оставить неиспользуемые using в нескольких файлах → Alt+Enter → «Fix All in Solution». Затем Shift+F6 на классе: файл переименуется вслед; Ctrl+H — Type Hierarchy, Ctrl+клик на Console — декомпилят read-only.

4:00

Отладка с exception breakpoint

Run | View Breakpoints → «.NET Exception Breakpoints» уже включены. Debug проекта: остановка на исключении, $exception в Evaluate, Async Call Stack, Set Value в Variables, ПКМ → Set Next Statement. Показать Condition / Hit count / Log message у точки.

5:30

Тесты с покрытием

Окно Unit Tests → Explorer → выделить класс → Run with Coverage (нужен coverlet.collector). Дерево из TRX после завершения, Rerun Failed, полосы в gutter, окно .NET Coverage и проценты в дереве.

7:00

NuGet

Окно NuGet → поиск → «+» в строке → установка идёт в Build и Log, restore сам. Показать multiple у пакета с разными версиями и completion версии в .csproj. Alt+Shift+N — Quick List.

8:00

EF Core: миграции

Меню .NET → EF Core → Add Migration…: startup project и DbContext подобраны, предпросмотр команды внизу. Окно EF Core → Refresh Status → applied / pending, «Update Database to Here».

9:00

.NET Monitor: memory dump

Окно .NET Monitor → процесс из IDE → графики. Heap Snapshot дважды → Δ Bytes; Memory Dump → тип → объект → Who Holds It; вкладка SOS Console: dumpasync. Save Dump As… для VS / WinDbg.

9:30
Подготовка перед демо. Settings | Tools | .NET → .NET Tools → Install у roslyn-language-server (нужен runtime .NET 10), dotnet-debugger-dap, dotnet-ef, dotnet-counters / dotnet-stack / dotnet-gcdump / dotnet-dump. Для Project Errors по solution включить «Compiler diagnostics for: fullSolution» в Settings → .NET → Language Server. Живая площадка — debug-playground/ в репозитории (Console / Lib / Web / MultiTarget / Tests, маркеры // BP:).
